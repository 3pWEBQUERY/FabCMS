# Nova

Ein CMS, zwei Modi. **Studio** für Menschen, die einfach ihre Website pflegen wollen – direkt auf der Seite klicken und schreiben. **Werkbank** für alle, die mehr wollen: eigene Inhaltstypen, CSS, Code-Ansicht pro Block, REST-API, Webhooks, SQL. Beide Modi arbeiten auf denselben Daten; umschalten mit <kbd>⌘</kbd>/<kbd>Ctrl</kbd> + <kbd>.</kbd>.

Gebaut nach der PRD «Nova CMS» (Okt. 2026). Gehostet auf **Railway** mit **Railway Postgres** und **Railway Bucket**.

---

## Auf Railway in Betrieb nehmen

1. **Projekt anlegen** und dieses Repository als Service verbinden. Railway erkennt `railway.json` und baut mit dem `Dockerfile`.
2. **Postgres hinzufügen** (Create → Database → PostgreSQL).
3. **Bucket hinzufügen** (Create → Bucket, Region wählen).
4. Im Nova-Service unter **Variables** setzen (Variable References):

   | Variable | Wert |
   |---|---|
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `BUCKET` | `${{Bucket.BUCKET}}` |
   | `ENDPOINT` | `${{Bucket.ENDPOINT}}` |
   | `REGION` | `${{Bucket.REGION}}` |
   | `ACCESS_KEY_ID` | `${{Bucket.ACCESS_KEY_ID}}` |
   | `SECRET_ACCESS_KEY` | `${{Bucket.SECRET_ACCESS_KEY}}` |

   Alternativ den AWS-SDK-Preset von Railway nutzen («Automatically provisioning the variables») – Nova versteht auch `AWS_ACCESS_KEY_ID`, `AWS_ENDPOINT_URL`, `AWS_S3_BUCKET_NAME` usw. Wenn der Credentials-Tab des Buckets «path-style» verlangt: `S3_FORCE_PATH_STYLE=true`.
5. **Networking → Generate Domain.** `PUBLIC_URL` ist nicht nötig, Nova liest `RAILWAY_PUBLIC_DOMAIN`.
6. **Deploy.** Migrationen laufen beim Start automatisch (mit Advisory-Lock, also sicher bei parallelen Deploys).
7. In den **Deploy-Logs** steht ein **Einrichtungscode**:

   ```
   ┌──────────────────────────────────────────────┐
   │  Einrichtungscode: 482-913                   │
   ```

   Öffne `https://<deine-domain>/admin`, gib den Code ein und leg dein Konto an. Der Code verhindert, dass jemand Fremdes eine frisch deployte Instanz übernimmt. Wer ihn fest setzen will: `NOVA_SETUP_CODE`.
8. Der Setup-Assistent stellt fünf Fragen (Sparte, Name, Vorlage und Stil mit Live-Vorschau, Domain, Modus) und legt eine fertige Website mit echten Beispielinhalten an. Besucher sehen eine «Hier entsteht etwas»-Seite, bis du im Dashboard auf **Website veröffentlichen** klickst.

### Eigener Erweiterungskatalog

Nova bringt geprüfte Erweiterungen mit (Werkbank → Einstellungen → Erweiterungen). Wer eigene verteilen will – eine Agentur für ihre Kundschaft etwa –, legt die Manifeste als JSON in einen Ordner, erzeugt einmal ein Schlüsselpaar und signiert den Katalog:

```bash
node scripts/extensions-catalogue.mjs keygen > schluessel.txt     # privaten Schlüssel gut aufbewahren
node scripts/extensions-catalogue.mjs sign erweiterungen/ privat.pem > katalog.json
```

`katalog.json` irgendwo per HTTPS ablegen, `NOVA_EXTENSIONS_URL` auf die Adresse und `NOVA_EXTENSIONS_KEY` auf den ausgegebenen öffentlichen Schlüssel setzen. Ändert jemand den Katalog ohne Schlüssel, zeigt Nova ihn nicht an und sagt warum. Ein Manifest beschreibt nur, was Nova ohnehin kennt (`src/shared/extensions.ts`): Inhaltstypen, Hooks, Formulare, Sektionen und CSS ohne externe Quellen – Nova prüft jedes vor der Installation vollständig.

### Altersprüfung mit der E-ID

Für Websites, die eine echte Altersverifikation brauchen, prüft Nova das Alter mit der staatlichen E-ID in der App swiyu. Die Prüfung selbst (OID4VP, Signatur, Aussteller, Widerruf) übernimmt der **swiyu Generic Verifier** des Bundes – Open Source, als eigener Dienst betrieben:

1. Auf Railway einen Dienst aus dem Image `ghcr.io/swiyu-admin-ch/swiyu-verifier` mit eigener Postgres-Datenbank anlegen und nach der [Anleitung des Bundes](https://github.com/swiyu-admin-ch/swiyu-verifier) einrichten (Verifier-DID und Schlüssel, `EXTERNAL_URL` = öffentliche Adresse des Dienstes – die Wallet muss sie erreichen). Zusätzlich `ADDITIONAL_AUDIT_INFORMATION_CREDENTIAL_SUBJECT_DATA_ENABLED=true` setzen: Nova liest den bestätigten Wert und nicht nur «Prüfung erfolgreich».
2. Die Management-API (`/management/api`) nur im privaten Netz erreichbar lassen und in Nova `SWIYU_VERIFIER_URL=http://${{verifier.RAILWAY_PRIVATE_DOMAIN}}:8080` setzen, dazu `SWIYU_ISSUER_DIDS` (für die Beta-ID die DID des Beta-Ausstellers aus der swiyu-Dokumentation, später die des E-ID-Ausstellers) und bei Bedarf `SWIYU_VCT`.
3. In Nova unter **Einstellungen → Rechtliches → Altersschranke** «E-ID des Bundes (swiyu)» wählen.

Besucher scannen dann einen QR-Code (oder öffnen swiyu direkt auf dem Handy) und geben eine einzige Angabe frei: bei 16 und 18 Jahren nur `age_over_16` bzw. `age_over_18`, bei anderen Grenzen das Geburtsdatum, das Nova einmal vergleicht und nicht speichert. Bis dahin liefert die Website keine Inhalte aus – Seiten enthalten nur die Schranke; Feed, Content-API (ohne Token) und hochgeladene Bilder, Dateien und Videos bleiben zu (ausser Logo und Favicon), danach werden Medien nur privat zwischengespeichert, nie in einem geteilten Cache.

### Eigene Domain

In Railway: Service → Settings → Networking → Custom Domain. Den angezeigten CNAME beim Domain-Anbieter eintragen. In Nova unter **Einstellungen → Domain** die Adresse hinterlegen – dort steht dieselbe Anleitung für Laien.

### Was wo gespeichert wird

- **Postgres:** Inhalte (JSONB), Versionen, Einstellungen, Formulare, Kontakte, Bestellungen, Statistik.
- **Bucket:** Original-Uploads, alle Bildvarianten (AVIF/WebP/JPEG, on-the-fly erzeugt und gecacht), Web-Fassungen der Videos, Social-Vorschaubilder, tägliche Sicherungen (`backups/`, 30 Tage).
- Railway-Buckets sind privat. Bildvarianten liefert Nova selbst aus (unveränderliche URLs, `Cache-Control: immutable`), grosse Dateien wie Videos und Downloads per kurzlebiger Presigned-URL direkt aus dem Bucket (Bucket-Egress ist bei Railway gratis, Range-Requests für Video funktionieren).

## Lokal entwickeln

```bash
npm install
cp .env.example .env            # DATABASE_URL auf ein lokales Postgres
npm run dev                     # Website :3000, Admin mit HMR :5173/admin/
npm test                        # Unit- und Integrationstests (brauchen Postgres, siehe TEST_DATABASE_URL)
npm run typecheck
npm run build && npm start      # Produktions-Build
```

Ohne Bucket-Variablen speichert Nova Dateien unter `.data/uploads` – praktisch lokal, auf Railway aber flüchtig.

## Architektur

Ein TypeScript-Monolith mit Headless-Kern – Admin, Website und externe Apps sprechen dieselben Daten an.

```
src/
  shared/    Feld- und Block-Schemas, Content-Typen, Rollen, SEO-Coach, Sanitizer – von Server und Admin geteilt
  server/    Hono-Server: Auth, API, Medien (sharp + S3), Shop, Statistik, Scheduler, Backups, Export
  site/      Website-Renderer: 40 Blöcke, 4 Themes, JSON-LD, Seiten-Templates, Client-Scripts
  admin/     React-Admin: Studio/Werkbank, On-Page-Editor, ⌘K, Setup-Assistent
migrations/  SQL-Migrationen
test/        Vitest: Unit + Integration gegen echtes Postgres
```

**Entscheide und Begründungen**

- **Renderer: eigenes serverseitiges Rendering statt Astro/Next.** Die PRD lässt den Entscheid offen. Für den Editor zählt, dass exakt derselbe Code die Live-Seite und die bearbeitbare Leinwand rendert – Blöcke sind reine Funktionen `props → HTML`. Öffentliche Seiten laden genau ein Script (`site.js`, 5 KB unkomprimiert) für Statistik, Zwei-Klick-Einbettungen, Lightbox und Warenkorb; alles funktioniert auch ohne JavaScript. CSS ist inline und pro Seite gekürzt: Von den Regeln aller Blöcke und Module (≈ 80 KB) bleibt nur, was die Seite oder eines ihrer Skripte brauchen kann – eine Regel fällt nur weg, wenn jeder ihrer Selektoren eine Klasse verlangt, die weder im HTML noch in den Skripten vorkommt; eigenes Werkbank-CSS, Editor und Vorschau bleiben unberührt (typisch 35 statt 80 KB, HTML gzip rund 11 statt 20 KB; auf 38 Seiten in zwei Bildschirmbreiten pixelgleich mit dem vollen CSS geprüft). Schriften selbst gehostet und vorgeladen; Bistros Fraunces ist fest auf SOFT 100 instanziiert (37 statt 62 KB, `scripts/instance-fonts.py`).
- **Ein Datenmodell:** Seiten, Beiträge, Produkte, Gerichte, Projekte, Profile und eigene Typen sind alle `entries` mit JSONB-Daten, einer Arbeitskopie (`data`) und einer Live-Kopie (`published_data`).
- **On-Page-Editor:** Die Seite wird im iframe im Bearbeitungsmodus gerendert. Ein kleines Bridge-Script macht Textfelder direkt bearbeitbar, zeichnet Auswahl, «+»-Einfügepunkte und Drag-Griffe (Nachbarn weichen live aus) und meldet Änderungen ans Admin. Das Admin hält Daten und Verlauf, speichert automatisch (Statuspunkt statt Spinner) und lässt Blöcke nach Inspector-Änderungen neu rendern.
- **Schutzzonen** werden serverseitig erzwungen: Ein Studio-Request kann gesperrte Blöcke nicht verschieben, umgestalten oder löschen – auch nicht mit einem manipulierten Request.
- **Ein Prozess, ein Replica.** Scheduler (geplantes Veröffentlichen, Backups, Aufräumen), Rate-Limits und Seiten-Cache leben im Prozess. Für mehrere Replicas müssten diese nach Postgres/Redis wandern.

## Was umgesetzt ist

**Editor & Inhalte**
- Visueller On-Page-Editor: direkt auf der Seite tippen, Fliesstext mit Formatierungsleiste, Blöcke per Drag & Drop oder Pfeiltasten, «+» zwischen Abschnitten, Duplizieren, Entfernen mit «Rückgängig».
- Eigenes Icon-Set für Website-Inhalte: 300 Symbole im selben 20-px-Raster wie das Admin (1,5 px Strich) – zusammen mit den 100 Admin-Icons rund 400 –, gruppiert nach Essen & Trinken (bis Fondue, Gipfeli und Cervelat), Handwerk & Haus, Schönheit & Pflege, Gesundheit, Laden & Versand, Unterwegs & Zugang (rollstuhlgängig, Hunde willkommen, Parkplatz, Lift, Bergbahn …), Sport & Freizeit (bis Jasskarten), Kultur & Bildung, Büro & Finanzen, Alltag (bis Schweizerkreuz) sowie Natur & Jahreszeiten. Im Raster und in der Aufzählung wählbar (statt Bild bzw. statt Nummer), mit Suche auf Deutsch («Velo», «Kaffee»); auf der Website als Inline-SVG in der Akzentfarbe, rein dekorativ. Die Auswahl im Admin zeigt genau die Zeichnung, die auf der Website erscheint.
- 40 Blöcke: Einstieg (3 Varianten), Text, Text mit Bild, Bild, Galerie (Raster/Mosaik/Streifen, Lightbox), Video (YouTube/Vimeo im Datenschutzmodus mit Zwei-Klick, eigene Videos), Aufzählung (nummeriert/Preisliste/Spalten), Aufruf, FAQ (mit FAQPage-JSON-LD), Stimmen, Zitat, Zahlen, Preise, Team, Logos, Knöpfe, Abstand, Formular, Reservation, Events & Kurse, Immobilien, Spenden, Newsletter-Anmeldung, Mitgliedschaft, Kontaktangaben, Öffnungszeiten (mit «jetzt geöffnet»), Karte (OpenStreetMap, Zwei-Klick), Beiträge, Produkte, Speisekarte, Projekte, Profile, Raster (2–4 Spalten mit Bild, Titel, Text, Link), Ablauf & Chronik, Tabelle (auf dem Handy jede Zeile eine Karte), Vorher/Nachher (Schieber per Maus, Finger oder Pfeiltasten), Hinweis (z. B. Betriebsferien, auf Wunsch nur von–bis sichtbar), Downloads (mit Typ und Grösse), Wiederverwendbare Sektion, Eigener Code (Werkbank, im Studio nur die Platzhalter als Felder).
- Responsive Vorschau (Computer/Tablet/Handy), Abstände und Ausblenden pro Breakpoint.
- Vorschau teilen (Menü neben «Veröffentlichen»): ein geheimer Link zeigt den aktuellen Entwurf jemandem ohne Konto – Kundin, Chef, Druckerei –, immer mit dem zuletzt gesicherten Stand, mit einem Band «Vorschau – noch nicht veröffentlicht» und dem Ablaufdatum. Gültig 1, 7 oder 30 Tage (höchstens 90), mit Notiz für wen, Anzahl Aufrufe und letztem Aufruf; jederzeit zurückziehbar. Nie im Suchindex, nie im Cache; abgelaufene Links zeigen nur einen Hinweis.
- Design-Panel pro Block (Visual Editor): Hintergrund (Farbe, Verlauf mit Winkel und Farbstopps, Bild mit Ausschnitt, stehend beim Scrollen, Überlagerung), Abstände als Box-Modell (Werte ziehen wie in Figma, Shift für alle Seiten, Alt für die gegenüberliegende), Grösse (Inhaltsbreite, Mindesthöhe bis ganzer Bildschirm, Inhalt oben/mittig/unten), Text & Farben (Schrift, Grösse, Gewicht, Zeilenhöhe, Laufweite, Ausrichtung, Schreibung, Text- und Akzentfarbe), Rahmen & Ecken (einzeln), Effekte (Schatten, Deckkraft, Unschärfe, Glas, Verschieben, Drehen, Skalieren), Position (Werkbank). Jeder Wert pro Bildschirmgrösse – Computer vererbt an Tablet, Tablet an Handy, wie bei Webflow; Punkte zeigen, was hier gesetzt (blau) oder übernommen ist (orange) – und für Hover mit Übergangsdauer. Farben kommen aus dem Theme (auch mit Deckkraft), so passt alles auch nach einem Theme-Wechsel. Schnellstile (schwebende Karte, Akzentfläche, Umgekehrt, Leuchten, Glas, ganzer Bildschirm), Design kopieren und einfügen. Änderungen erscheinen sofort im Editor, noch bevor der Server antwortet; jeder Wert wird beim Erzeugen des CSS geprüft.
- Inhaltsschleife (Novas Abfrage für dynamische Listen, im freien Layout unter «Aus dem CMS»): holt Einträge jedes Inhaltstyps – auch eigener – nach Regeln: Kategorie, Schlagwort, «Nur wenn»-Bedingungen auf beliebige Felder (bis vier, Listen- und Ja/Nein-Felder inklusive), nur kommende oder vergangene bei Inhalten mit Datum (in der Zeitzone der Website), «wie der Eintrag dieser Seite» (gleiche Kategorie oder gemeinsames Schlagwort) und den Eintrag der Seite auslassen – für «Mehr zum Thema» auf Eintragsseiten und in Seitenvorlagen. Reihenfolge nach Datum, Titel, eigener Reihenfolge, einem Feld oder zufällig, Überspringen, Blättern mit eigenem Parameter pro Schleife (zwei Schleifen blättern unabhängig) und ein eigener Text, wenn nichts passt. Jeder Eintrag erscheint im Design des ersten, mit den Feld-Bindungen der Elemente.
- Dynamische Daten an jedem Element: Überschrift, Text, Knopf, Bild und Container-Link lassen sich unter «Dynamische Daten» mit Daten der Website verbinden – Name, Untertitel, Telefon (auch als Anruf-Link), E-Mail (auch als Mail-Link), Adresse, «jetzt geöffnet/geschlossen», aktuelles Jahr, «© Jahr und Name», Startseite, Logo – überall, auch in Kopf- und Fusszeile. In Schleifen, Seitenvorlagen und im eigenen Layout eines Eintrags kommen seine Felder dazu, bei Beiträgen auch Autor:in und Lesezeit. Ein Wert, der nicht passt (ein Name als Link), oder Eintragsdaten ohne Eintrag lassen das Eingetippte stehen.
- Kopfzeile, Fusszeile und Archive gestalten: Ein Klick auf Kopf- oder Fusszeile im Editor bietet «Kopfzeile frei gestalten» bzw. «Fusszeile frei gestalten» an – mit einem Startentwurf aus Logo und Menü bzw. Name, Adresse, Öffnungszeiten, Fusszeilen-Spalten, Copyright und rechtlichen Links. Veröffentlicht ersetzt sie die des Themes auf allen Seiten; offline genommen ist die des Themes zurück. Jeder Inhaltstyp mit Übersicht bekommt eine «Archiv-Vorlage»: Titel der Übersicht samt gewähltem Filter, Kategorien-Filter und eine Inhaltsschleife mit «Dieses Archiv zeigen», die Inhaltstyp, Kategorie, Schlagwort und Seite aus der Adresse liest (`/journal?kategorie=Touren&seite=2`). Neue Elemente in der Gruppe «Website»: Logo, Menü (Hauptmenü mit Handy-Menü, Warenkorb, Konto und Sprachen; Fusszeilen-Spalten; Impressum/Datenschutz/AGB; Social Media), Öffnungszeiten (mit «jetzt geöffnet») und unter «Aus dem CMS» der Kategorien-Filter; dazu die dynamische Angabe «Titel dieser Seite oder Übersicht».
- Scroll-Effekte und visuelle Effekte: Unter «Animation → Beim Scrollen» kommen zu Tiefe, Ausblenden, Wachsen und Gleiten neu Drehen, Schärfe (scharf in der Bildmitte), Aufziehen (das Bild öffnet sich aus einem Fenster) und Einfärben (aus Graustufen in Farbe) – bei Elementen bewegt sich das Element selbst. Überschriften und Texte erscheinen «Wort für Wort» oder «leuchten beim Scrollen auf» (Wort um Wort, an die Scrollposition gebunden); im Editor bleibt der Text zum Schreiben ganz, ohne JavaScript und bei «Bewegung reduzieren» steht er einfach da. Jedes Element reagiert auf Wunsch selbst auf die Maus: anheben, vergrössern, leuchten, 3D-Neigen oder magnetisch (zieht sich sanft zum Zeiger). Im Design-Panel neu: Verlaufstext, Graustufen, Sättigung, Helligkeit (auch für Hover – etwa grau, bei Hover farbig), Mischmodus und Formen zum Ausschneiden (Kreis, Bogen, Raute, schräge Kante, organisch, Sechseck).
- Eigene Inhaltstypen im Studio: Unter Inhalte → «Eigener Inhaltstyp» fragt Nova «Was möchtest du sammeln?» und bietet Leistungen, Team, Rezepte, Stellen, Kundenstimmen, häufige Fragen, Partner oder einen leeren Typ an – je mit passenden Feldern, die sich gleich umbenennen, ordnen, ergänzen und als Pflicht markieren lassen (Beschriftung und Art genügen, Schlüssel entstehen von selbst). Wer eigene Seiten wählt, bekommt Detail- und Übersichtsadresse aus dem Namen (belegte Adressen werden nummeriert) und auf Wunsch Seitenvorlage und Archiv-Vorlage im freien Layout als Entwurf, schon mit Bild, Kurzbeschreibung und Kategorien-Filter verbunden. In jeder Inhaltsliste öffnet «Felder» dasselbe für bestehende Typen; bei eingebauten Typen nur die eigenen Felder neben denen von Nova, bei Feldern mit Einträgen bleibt die Art fest, Entfernen fragt nach.
- Shop-Elemente im freien Layout (Gruppe «Shop», nur mit eingeschaltetem Shop): Preis (mit Statt-Preis, Rabatt in Prozent, bei Varianten «ab»), In den Warenkorb (mit Variantenwahl, ausverkaufte Varianten nicht wählbar, auf Wunsch Menge, legt ohne Neuladen in den Warenkorb, in einem verlinkten Container ein Knopf zur Produktseite statt eines Formulars), Lagerstatus («An Lager», «Nur noch 3 Stück», «Ausverkauft») und Sterne aus den freigegebenen Bewertungen. Jedes zeigt das Produkt der Inhaltsschleife oder Produktseite – oder ein von Hand gewähltes. Die Inhaltsschleife kennt für Produkte «Im Angebot», «Bestseller der letzten 90 Tage», «Passt zum Produkt dieser Seite» und «Nur was an Lager ist»; die fertige Vorlage «Produkte im Angebot» setzt Bild, Name, Sterne, Preis und Warenkorb-Knopf in ein Raster.
- «Nur zeigen, wenn …» für jedes Element im freien Layout: bis zu vier Bedingungen, die alle stimmen müssen – angemeldetes Mitglied, bezahlte Mitgliedschaft oder nicht angemeldet, Zeitraum (in der Zeitzone der Website), Wochentage, jetzt geöffnet oder geschlossen, Sprache, Warenkorb leer oder nicht, ein Link-Parameter (z. B. `?aktion=herbst` aus dem Newsletter) und in Schleifen und Vorlagen ein Feld des Eintrags («hat ein Bild», «Schlagwort Vegan»). Geprüft wird auf dem Server: was nicht zutrifft, steht gar nicht im HTML und auch nicht in Beschreibung oder Suche. Im Editor bleibt das Element sichtbar, gestrichelt markiert und blass, wenn es gerade nicht erscheinen würde; in den Ebenen trägt es ein Filter-Zeichen. Dieselben Bedingungen gibt es für ganze Blöcke jeder Art (Design → Sichtbarkeit & Sprungmarke) – etwa ein Aktionsbanner nur am Wochenende oder ein Hinweis nur für angemeldete Mitglieder.
- Countdown, Inhaltsverzeichnis, Teilen und Lesefortschritt als Elemente: Der Countdown zählt Tage, Stunden, Minuten und Sekunden bis zu einem festen Zeitpunkt oder – über «Dynamische Daten» – bis zum Datum des Eintrags (z. B. Beginn eines Events) und zeigt danach einen eigenen Satz oder verschwindet. Das Inhaltsverzeichnis stellt sich aus den Zwischentiteln der Seite zusammen (H2 oder H2 und H3, auf Wunsch nummeriert), gibt Titeln ohne Sprungmarke eine aus ihrem Text und bleibt bei weniger als zwei Titeln verborgen. «Teilen» bietet Link kopieren, E-Mail, WhatsApp, LinkedIn, Facebook und X als normale Links – ohne Skripte der Netzwerke; in einer Schleife wird der Eintrag geteilt. Der Lesefortschritt ist ein dünner Balken oben oder unten, der beim Scrollen wächst (CSS, mit kleinem Skript für ältere Browser).
- Alle Geräte nebeneinander: Ein vierter Knopf neben Computer, Tablet und Handy zeigt die Seite in allen drei Grössen gleichzeitig, jede in ihrer echten Breite und passend verkleinert, so wie Besucher den gesicherten Entwurf sehen. Die drei scrollen gemeinsam, laden nach jedem Speichern an derselben Stelle neu, und «Hier bearbeiten» springt in die gewählte Grösse zurück (Escape schliesst die Ansicht).
- Filter für Schleife: Ein Element, mit dem Besucher eine Inhaltsschleife derselben Fläche selbst eingrenzen – Suchfeld (Titel und Kurztexte), Kategorien als Knöpfe oder Auswahl, Schlagwörter, Reihenfolge (neueste, älteste, A–Z, bei Produkten nach Preis). Ein gewöhnliches Formular, das ohne Skript funktioniert und sich mit Skript bei jeder Wahl selbst abschickt; die Parameter gehören der Schleife (`?kategorie-<id>=…`), in einer Archiv-Vorlage die der Übersicht, andere Parameter der Seite bleiben erhalten, «Zurücksetzen» erscheint, sobald etwas gewählt ist, und ohne Treffer sagt die Schleife es. Zahlenfelder wie Preise sortieren jetzt als Zahlen (vorher als Text: 100.– vor 9.–).
- Galerie als Element: mehrere Bilder als Raster (gleich gross, klein/mittel/gross), Mosaik oder Streifen zum Wischen; ein Klick öffnet sie gross mit Blättern per Pfeiltasten (abschaltbar). Über «Dynamische Daten» zeigt sie die Bilder des Eintrags – etwa die Fotos jedes Produkts in einer Schleife oder in der Produktvorlage. Die Bilder zählen in der Mediathek als verwendet.
- Farben dieser Seite: Ein Knopf in der Editor-Leiste listet alle Farben, die Blöcke, Elemente und Komponenten-Varianten der Seite selbst setzen – Text, Hintergrund, Rahmen, Akzent, Überlagerung, Verläufe, Verlaufstext und Schatten, auf allen Bildschirmgrössen und bei Hover –, mit der Zahl der Stellen. Ein Klick ersetzt eine Farbe überall auf der Seite; liegt eine eigene Farbe nah an einer Theme-Farbe, schlägt Nova vor, sie durch diese zu ersetzen, damit die Seite einem Theme-Wechsel folgt. Gesperrte Blöcke bleiben unberührt.
- Menü, Kopf- und Fusszeile im Editor: Ein Klick auf die Kopfzeile öffnet rechts Name, Logo, Hauptmenü mit Unterpunkten (Ziehen zum Ordnen, Seiten als Vorschlag) sowie Knopf und Verhalten; ein Klick auf die Fusszeile Text, Link-Spalten und Social-Media-Links. «Speichern – auf allen Seiten» schreibt in die Website-Einstellungen und zeichnet Kopf- und Fusszeile auf der Fläche sofort neu – dieselben Felder wie unter Einstellungen → Navigation.
- Einträge aus der Fläche: Fährt man im Editor über eine Karte einer Inhaltsschleife, erscheint «‹Titel› bearbeiten» – ein Klick öffnet genau diesen Eintrag (auch die blassen Kopien nach der ersten). Im Inspektor der Schleife legt «Neuer Eintrag in ‹Typ›» einen Entwurf an, mit Kategorie und Schlagwort der Schleife schon gesetzt, und öffnet ihn; «Alle ansehen» führt zur Liste.
- Website-Daten direkt am Element: Zeigt ein Element Name, Untertitel, Telefon, E-Mail, Adresse, Copyright oder Logo der Website – über «Dynamische Daten» oder als Logo-, Öffnungszeiten- oder Menü-Element –, stehen genau diese Angaben im Inspektor zum Bearbeiten: Telefon am Anruf-Knopf, Öffnungszeiten mit Hinweis am Öffnungszeiten-Element, Hauptmenü, Fusszeilen-Spalten oder Social-Links am Menü. «Speichern – auf allen Seiten» schreibt sie in die Einstellungen und zeichnet die Seite samt Kopf- und Fusszeile neu.
- Neue Seite beim Verlinken: Jedes Link-Feld – an Elementen und Blöcken, Links mit Beschriftung, Hauptmenü, Fusszeile und der Link-Knopf der Textformatierung auf der Fläche – schlägt die Seiten der Website vor. Steht dort etwas, das es noch nicht gibt («/team» oder «Unser Team»), bietet die Liste «Neue Seite ‹Unser Team› anlegen»: Nova legt sie als Entwurf an, setzt den Link auf ihre Adresse und erinnert daran, sie zu veröffentlichen – mit «Öffnen» direkt zu ihr. Externe Adressen, E-Mail, Telefon, Sprungmarken und Dateien bleiben, wie sie sind.
- Verlinkte Entwürfe beim Veröffentlichen: Verlinkt ein Inhalt auf Seiten oder Einträge, die noch Entwürfe sind – über Knöpfe, Link-Felder oder Links im Text –, nennt «Veröffentlichen» sie und bietet an, alle zusammen zu veröffentlichen (auch geplant zum selben Zeitpunkt), nur diesen Inhalt oder abzubrechen. Dasselbe beim Sammel-Veröffentlichen in Listen und beim Speichern von Hauptmenü, Fusszeile, Kopfzeilen-Knopf und Social-Links; wer nicht veröffentlichen darf, speichert und erfährt, welche Links noch ins Leere führen. So führt kein frisch gesetzter Link auf der Website ins Leere.
- Bereiche auf der Fläche ziehen: Ein ausgewählter Bereich hat unten einen Griff für die Höhe und an der Inhaltsspalte links und rechts Griffe für die Breite (symmetrisch, wie «Boxed» bei Elementor). Beim Ziehen zeigt Nova das Mass, rastet bei halbem, dreiviertel und ganzem Bildschirm sowie bei voller Breite ein (Shift: ohne Einrasten) und speichert für die gerade gewählte Bildschirmgrösse. Doppelklick auf einen Griff setzt zurück.
- Bewegter Hintergrund für Bereiche: Unter Design → Hintergrund wählt man «Video» oder «Diashow». Das Video läuft stumm in Schlaufe aus Novas Web-Fassung, mit Standbild; auf dem Handy zeigt es nur das Standbild, ausser man schaltet «Auch auf dem Handy abspielen» ein. Die Diashow blendet bis zu acht Bilder ineinander, auf Wunsch mit langsamem Zoom (Ken Burns), reines CSS ohne Skript. Die Überlagerungsfarbe liegt auch darüber, der Inhalt bleibt vorne; wer «weniger Bewegung» eingestellt hat, sieht Standbild oder erstes Bild.
- Formtrenner: Oben und unten an jedem Bereich lässt sich eine Form setzen – Welle, Wellen, Bogen, Schräg, Spitze, Zickzack, Berge –, mit Höhe, Farbe (ohne Angabe die des Seitenhintergrunds, damit der Bereich in den nächsten fliesst), gespiegelt, umgedreht und auf Wunsch vor dem Inhalt. Als SVG ohne Bilddatei, auf dem Handy etwas flacher; die Auswahl zeigt jede Form als kleine Vorschau.
- Spaltenaufteilung: Raster-Container haben ungleiche Spalten – im Design-Panel unter «Aufteilung» als Vorlagen (1 : 2, 2 : 1, 1 : 3, 1 : 2 : 1 …) mit Vorschau oder als Verhältnis zum Eintippen. Auf der Fläche sitzt zwischen zwei Spalten ein Griff; Ziehen zeigt die Anteile in Prozent und rastet beim Loslassen auf einfache Verhältnisse ein, wenn sie nah sind. Pro Bildschirmgrösse – auf dem Handy bleibt «1 Spalte» eine Spalte.
- Bereichsvorlagen: «Als Vorlage speichern» in der Werkzeugleiste oder im Kontextmenü eines Bereichs legt ihn unter einem Namen ab. Unter «Block einfügen» → «Meine Vorlagen» steht er dann auf jeder Seite bereit, als Kachel mit verkleinerter Live-Vorschau, – jedes Mal als eigene Kopie mit neuen ids, die man frei ändert (anders als eine wiederverwendbare Sektion oder Komponente, die verknüpft bleiben). Verwaltet werden die Vorlagen unter Inhalte → Sektionen, Art «Bereichsvorlage».
- Überlagerung als Verlauf: Unter Design → Hintergrund liegt über Bild, Video oder Diashow auf Wunsch ein Verlauf – mit Vorlagen «Unten dunkel», «Oben dunkel», «Links dunkel», «Ränder dunkel» und «Akzent von unten», danach frei einstellbar. So bleibt Text auf Bildern lesbar, ohne das ganze Bild abzudunkeln.
- Elemente «Karte» und «Icon-Liste»: Die Karte zeigt OpenStreetMap mit Stecknadel am Standort der Website oder an einem eigenen Ort, den man im Inspektor per Adresse sucht (Nominatim, höchstens eine Anfrage pro Sekunde, gemerkt). Sie lädt erst nach einem Klick – vorher geht nichts an OpenStreetMap –, mit Ausschnitt, Höhe und «Route planen»; sind Karten in den Einstellungen aus, steht ein Link da. Die Icon-Liste setzt vor jeden Eintrag ein Symbol aus Novas Satz, untereinander oder nebeneinander, auf Wunsch verlinkt; die Texte schreibt man direkt auf der Fläche.
- Baukasten wie in einem Page Builder: Links neben der Fläche liegt eine feste Leiste mit drei Reitern – «Elemente» (alle Elemente und die eigenen Komponenten), «Blöcke» (freie Layouts, eigene Vorlagen mit Vorschaubild, alle Blöcke und wiederverwendbaren Sektionen) und «Ebenen» (der Aufbau der Seite bis zum einzelnen Element). Alles lässt sich auf die Seite ziehen: Ein Element landet im freien Layout genau an der Stelle unter dem Zeiger (der Container leuchtet, eine Linie zeigt den Platz), anderswo zwischen den nächsten zwei Blöcken in einem eigenen Layout; Blöcke und Vorlagen fügen sich zwischen zwei Blöcke ein, am Rand scrollt die Seite mit. Ein Klick setzt das Gewählte wie bisher hinter die Auswahl. Wer etwas auf der Seite anklickt, sieht rechts gleich dessen Einstellungen. Die Leiste blendet sich mit einem Knopf in der Kopfzeile aus und ein (der Browser merkt es sich); auf schmalen Bildschirmen bleibt alles wie bisher über «+». Geschützte Blöcke nehmen im Studio nichts an.
- Favoriten und «Zuletzt verwendet» im Baukasten: Ein Stern an jedem Element heftet es oben unter «Favoriten» an; darunter stehen die sechs zuletzt eingefügten – ob per Klick, Ziehen oder «+». Beides merkt sich der Browser, auch die Schnellauswahl hinter «+» zeigt die beiden Gruppen; beim Suchen treten sie zurück.
- Element «Vorher/Nachher»: der Bildvergleich mit Schieber jetzt auch als Element im freien Layout – neben Text in einer Spalte, in Containern und Komponenten. Mit Startposition des Schiebers, Format (3:2, 16:9, 4:3, Quadrat, Hochformat), eigenen Beschriftungen und einer Beschreibung für Screenreader; bedienbar mit Maus, Finger und Pfeiltasten.
- Element «Animierte Überschrift»: Text davor und danach direkt auf der Fläche, dazwischen bis zu acht Wörter, die wechseln (hochrollen, überblenden oder aufdecken, Sekunden pro Wort einstellbar) – oder ein Ausdruck, der beim Hinscrollen wie von Hand unterstrichen, umkreist, mit Leuchtstift markiert oder durchgestrichen wird. Im HTML steht der ganze Satz genau einmal («Wir backen Brot, Zöpfe, Torten jeden Morgen frisch.»), so lesen ihn Suchmaschinen, Screenreader, Seitenbeschreibung und Gliederung; wer weniger Bewegung möchte, sieht das erste Wort und die fertige Linie. Ebene H1 bis H4 wie bei der Überschrift.
- Sprungmarken für Elemente: Wie Blöcke kann jetzt jedes Element im freien Layout eine eigene Sprungmarke tragen (im Inspektor unter «Sprungmarke», aus «Kontakt & Anfahrt» wird beim Verlassen des Felds kontakt-und-anfahrt). Sie ersetzt die technische ID in der Seite, sodass Menüeinträge und Knöpfe mit #kontakt-und-anfahrt genau dorthin springen; auch das Inhaltsverzeichnis und Knöpfe, die ein Element ein- oder ausblenden, verwenden sie. Doppelte Marken im selben Layout meldet der Inspektor, gespeichert behält sie nur das erste Element; Kopien bekommen keine.
- Sprungmarken in jedem Link-Feld: Wer «#» tippt, bekommt die Sprungmarken der Seite vorgeschlagen – von Blöcken und Elementen, mit dem, was dort steht («#team · Unser Team»). Nach einer Seitenadresse mit «#» («/ueber-uns#») kommen die Marken jener Seite. Ob eine Marke auf der Seite schon vergeben ist, prüft der Inspektor jetzt über alle Blöcke und Layouts hinweg.
- Element «Hinweispunkte»: ein Bild mit bis zu zwölf Punkten, die beim Antippen eine kleine Karte mit Titel, Text und Link öffnen – für Zimmer, Produkte, Pläne oder ein Team-Foto. Im Inspektor setzt ein Tipp ins Bild einen neuen Punkt, Punkte lassen sich ziehen oder mit den Pfeiltasten verschieben. Als Plus, Nummer oder Punkt, auf Wunsch sanft pulsierend; die Karte öffnet sich weg vom nächsten Rand. Jeder Punkt ist ein natives Aufklapp-Element und funktioniert damit auch ohne Skript und mit der Tastatur; das Skript schliesst nur die anderen und reagiert auf Escape und Klicks daneben.
- Ebenen durchsuchen: Über den Ebenen (im Baukasten und unter «Aufbau») steht ein Suchfeld. Es findet Blöcke und Elemente nach Name, Art, Text und Sprungmarke, ohne auf Akzente zu achten, und zeigt bei jedem Treffer den Weg dorthin («2. Freies Layout › Kontaktbox»). Auch dieser Weg zählt: «kontaktbox knopf» findet den Knopf in der Kontaktbox. Ein Klick oder Enter wählt den Treffer auf der Seite aus, beim Darüberfahren leuchtet er auf, Escape leert die Suche.
- Eigenes CSS pro Element (Werkbank): Wie Blöcke haben Elemente in der Werkbank einen Reiter «Code» mit CSS-Klassen und CSS nur für dieses Element. «&» steht für das Element selbst, andere Selektoren gelten innerhalb davon, auch in @media-Regeln, z. B. «&:hover { rotate: -2deg }». Die Änderung ist auf der Fläche sofort sichtbar. Im Studio lässt sich der Code weder ändern noch entfernen, auch nicht, indem man das Element in ein anderes Layout verschiebt. Neue Elemente aus dem Studio bekommen keinen.
- Element «Flip-Box»: eine Karte mit Vorder- und Rückseite. Vorne Bild (abgedunkelt für den Text), Symbol, Titel und Text, hinten Titel, Text und ein Knopf. Sie dreht sich seitlich oder nach oben oder blendet über, und zwar beim Darüberfahren, wenn etwas darin den Fokus hat, oder auf dem Handy beim Antippen; ohne Knopf ist die Karte selbst mit der Tastatur erreichbar. Beide Seiten stehen im HTML, Suchmaschinen und Screenreader lesen alles; wer weniger Bewegung möchte, sieht den Wechsel ohne Drehung. Die Texte lassen sich direkt auf der Fläche bearbeiten.
- Element «Kundenstimme»: ein Zitat mit Sternen (0 bis 5, für Screenreader als «4 von 5 Sternen»), Foto, Name und Zusatz, als Karte, schlicht oder zentriert und gross. Zitat, Name und Zusatz lassen sich direkt auf der Fläche schreiben; mehrere nebeneinander in einem Raster ergeben eine Referenz-Wand.
- Interaktionen wie in Bricks und Webflow: Jedes Element kann bis zu sechs Interaktionen haben, je mit Auslöser (Klick, Darüberfahren, Sichtbarwerden), Aktion (ein- und ausblenden, zeigen, verbergen, gespeicherten Stil umschalten, hinscrollen) und Ziel (das Element selbst oder ein anderes im Layout). Beim Darüberfahren geht alles zurück, sobald der Zeiger das Element verlässt, und dasselbe gilt mit der Tastatur über den Fokus. Ein umgeschalteter Stil liegt über dem eigenen Design des Ziels. In der Werkbank lässt sich statt eines Stils eine eigene CSS-Klasse umschalten. Was per Klick reagiert und kein Link oder Knopf ist, wird für Tastatur und Screenreader zum Knopf, mit aria-expanded beim Ein- und Ausblenden. Kopien zielen auf die Kopie ihres Ziels. Die bisherige Knopf-Aktion «Beim Klick» bleibt.
- Grid-Platzierung wie in Webflow: Ein Raster kann eine feste Anzahl Zeilen haben und Lücken mit späteren Elementen füllen («Lücken füllen») oder Spalte um Spalte befüllt werden. Jedes Element darin bekommt unter «Platz im Raster» seine Startspalte, Spaltenbreite, Startzeile und Zeilenhöhe, pro Bildschirmgrösse (z. B. 2×2 gross auf dem Computer, eine Spalte auf dem Handy).
- Mehr Stil wie in Webflow: Textschatten (leicht, mittel, stark oder Leuchten in der Akzentfarbe), Textspalten (bis vier, wie in einer Zeitung), Rahmen nur auf gewählten Seiten (oben, unten, oben und unten, links, rechts), dazu 3D-Drehungen (nach hinten kippen, zur Seite drehen) mit einstellbarer Tiefe sowie Neigen. Textschatten, Drehungen und Neigen gehen auch im Hover-Zustand, mit Übergang – etwa eine 3D-Karte, die sich beim Darüberfahren gerade richtet.
- Zustände «Fokus» und «Gedrückt» wie in Webflow: Neben «Normal» und «Hover» gestaltet man im Design-Panel, wie ein Block oder Element aussieht, wenn es (oder etwas darin) mit der Tastatur angewählt ist, und während man darauf klickt oder tippt, etwa einen deutlichen Fokusrahmen oder einen Knopf, der beim Drücken etwas kleiner wird. Die Fläche zeigt den gewählten Zustand ohne Maus und Tastatur, jetzt auch für einzelne Elemente statt nur für den Block. Die Zustände gleiten wie Hover und erscheinen auch in gespeicherten Stilen und in der Stil-Übersicht; die Kontrastprüfung misst weiterhin den Normalzustand.
- «Folgt der Maus» wie Webflows «Mouse move in viewport»: Unter Animation bewegt sich ein Element dorthin, wo die Maus im Fenster ist, oder neigt sich in 3D zu ihr hin. Stärke und Gegenrichtung sind einstellbar; mehrere Ebenen mit verschiedener Stärke ergeben räumliche Tiefe. Ein einziger, pro Bildschirmbild gedrosselter Zuhörer bedient alle Elemente. Mit dem Finger und bei «weniger Bewegung» bleibt alles still, im Editor ebenfalls, damit sich nichts unter dem Klick wegbewegt.
- Elemente «Social-Profile» und «Nach oben scrollen» wie in Bricks: Social-Profile zeigt die Profile aus den Website-Daten als Symbole (Instagram, Facebook, LinkedIn, YouTube, X, TikTok, WhatsApp, E-Mail, sonst ein Globus), nur Symbole, Symbol und Name oder nur Namen, frei, im Kreis oder im Quadrat. Die Links lassen sich direkt im Inspektor unter «Website-Daten» pflegen, und eine Änderung gilt überall. «Nach oben scrollen» scrollt sanft an den Seitenanfang, auf Wunsch als schwebender Knopf unten rechts, der erst erscheint, wenn man ein Stück gescrollt hat. Die Beschriftung kommt in der Sprache der Besucher, eine eigene bleibt wie geschrieben.
- «Prüfung» wie das Audit-Panel von Webflow: Ein Schild in der Kopfzeile des Editors prüft die Seite, wie sie gerade auf der Vorschau steht, und zeigt die Zahl der Fehler. Gefunden werden Bilder ohne Beschreibung, Links ohne Text oder mit Ziel «#», Knöpfe ohne Beschriftung, fehlende oder doppelte H1, übersprungene Überschriften-Ebenen, leere Überschriften, Formularfelder ohne Beschriftung, Eingebettetes ohne Titel, doppelte Sprungmarken, Schrift unter 12 Pixel und Symbol-Klickziele unter 24 × 24 Pixel (WCAG). Fehler stehen vor Hinweisen, jeder mit einer Erklärung, was zu tun ist; ein Klick wählt die Stelle auf der Seite aus. Nach jeder Änderung wird neu geprüft.
- Design-Variablen wie in Webflow: Unter Einstellungen → Design legt man eigene Farben und Grössen an («Marke Grün», «Kartenabstand»), mit Farbwähler oder Längenfeld, auf Wunsch auch auf Basis einer Theme-Farbe («Akzent, 40 %»). Im Editor erscheinen sie in jedem Farbwähler und jedem Grössenfeld unter «Variablen», mit Namen und Vorschau statt Code, auch mit eigener Deckkraft. Auf der Website sind sie CSS-Variablen (--v-…) auf :root, und wer einen Wert ändert, ändert ihn überall. Beim Umbenennen bleibt die Kennung, damit nichts bricht; gelöschte Variablen fallen auf den Theme-Wert zurück. Nur echte Farben und Längen werden angenommen.
- Fliessende Schriftgrössen wie in Bricks: Neben «Grösse» gibt es «Fliessend bis». Aus «28px» und «64px» wird eine Schrift, die auf dem Handy (375 px breit) genau 28 und auf dem Computer (ab 1280 px) genau 64 Pixel gross ist und dazwischen gleichmässig wächst, ohne Sprünge an Bildschirmgrenzen (clamp() mit rem, damit sie mit der Schriftgrösse im Browser mitzoomt). Geht mit px und rem, auch abnehmend; sonst sagt das Panel, was fehlt.
- Element «Tabelle» für Preise, Öffnungszeiten oder technische Angaben: Jede Zelle und jede Spaltenüberschrift wird direkt auf der Seite angeklickt und geschrieben. Im Inspektor stehen dieselben Zellen als Raster mit «+ Zeile», «+ Spalte» und Entfernen (bis 6 Spalten und 60 Zeilen). «Aus Excel einfügen» übernimmt Zellen, die in Excel, Numbers oder Google Sheets kopiert wurden (auch CSV mit Strichpunkt oder Komma), wahlweise mit der ersten Zeile als Überschriften. Erste Spalte als Zeilentitel, letzte Spalte rechtsbündig für Preise, Zeilen abwechselnd hinterlegt. Auf dem Handy wird jede Zeile zur Karte, jede Zelle trägt die Überschrift ihrer Spalte.
- Arbeitsschritte im Verlauf wie in Elementor: Unter «Verlauf» → «Arbeitsschritte» steht jeder Schritt seit dem Öffnen mit Namen und Zeit – «Neu: Bild», «Gestaltet: Überschrift», «Verschoben: Container», «Feld «Titel» geändert». Ein Klick springt genau an diese Stelle zurück, auch zehn Schritte auf einmal; die übersprungenen Schritte bleiben ausgegraut darüber stehen und holen die Arbeit mit einem Klick zurück, solange nichts Neues geändert wird. Funktioniert auch bei gemeinsamer Bearbeitung in Echtzeit, dann nur mit den eigenen Schritten. «Fassungen» zeigt wie bisher die gesicherten Zwischenstände.
- Element «Diagramm»: Säulen, liegende Balken, Linie oder Ring – ohne Bibliothek und ohne JavaScript auf der Website. Werte im Inspektor eintippen («1’250», «12,5», «CHF 45.–» werden als Zahl erkannt) oder aus Excel, Numbers und Google Sheets einfügen: erste Spalte die Beschriftungen, daneben bis vier Reihen. Eine Reihe trägt die Akzentfarbe der Website, mehrere eine Palette aus acht Farben, die auch mit Farbsehschwäche unterscheidbar bleiben – für helle und dunkle Themes und invertierte Bereiche je passend abgestuft. Runde Achsenschritte mit Schweizer Tausendertrennzeichen, Werte direkt an den Säulen, beim Darüberfahren eine Beschriftung mit allen Reihen, Säulen wachsen beim Hereinscrollen. Ein Ring zeigt bis acht Stücke (der Rest wird «Andere»), in der Mitte das Total oder bei Prozent das grösste Stück. Screenreader lesen die Zahlen als Tabelle, die auf Wunsch für alle aufklappbar ist; auf dem Handy rutschen lange Beschriftungen über die Balken.
- Element «Fortschrittsbalken» für Kenntnisse, Auslastung oder ein Spendenziel: Beschriftungen direkt auf der Seite schreiben, Werte im Inspektor. «Voller Balken bei» 100 zeigt Prozent («85 %»), 5 und ohne Einheit eine Bewertung («4.5 / 5»). Beschriftung über dem Balken oder alles in einer Zeile, Dicke, runde oder eckige Enden, Wert ein- und ausblendbar. Die Balken füllen sich beim Hereinscrollen (nicht bei «Bewegung reduzieren») und sind für Screenreader echte Messwerte mit Beschriftung.
- Element «Brotkrumen»: der Weg zur aktuellen Seite («Startseite / Angebot / Kurse») frei platziert – im Inhalt, in einer selbst gestalteten Kopfzeile oder in einer Vorlage für Eintragsseiten. Trennzeichen Schrägstrich, Winkel, Pfeil oder Punkt; die Startseite als Wort, Haus-Symbol oder beides; die aktuelle Seite auf Wunsch weggelassen, lange Titel gekürzt. Steht das Element auf der Seite, verschwinden die Brotkrumen des Themes über dem Inhalt; Google erhält den Weg genau einmal als strukturierte Daten. Auf der Startseite fällt es weg, im Editor zeigt es ein Beispiel.
- Aufgeräumte Kopfleiste im Editor in drei Zonen: links Seite, Speicherstand, Baukasten und Rückgängig/Wiederholen; in der Mitte die Vorschaugrösse; rechts Seite, Aufbau, Kommentare und Verlauf auf einer Leiste, daneben «Prüfen» als Menü für Prüfung, Kontrast, Suchmaschinen und Farben – mit der Zahl offener Hinweise am Knopf. Raster, Tastenkürzel und Studio/Werkbank liegen im Menü «Mehr». Bei mittlerer Breite werden zuerst Titel und Beschriftungen kürzer, «Veröffentlichen» bleibt immer sichtbar.
- Struktur wie in Bricks: Im Baukasten steht zuoberst die Gruppe «Struktur» mit Section (ganze Breite, Abstand oben und unten, darin gleich ein Container), Container (Website-Breite, zentriert), Block (füllt seine Spalte), Div (ohne Vorgaben) und Spalten (2, 3, 4, 1/3 + 2/3, 2/3 + 1/3 – auf Tablet und Handy automatisch weniger). Eine Section ausserhalb eines Layouts bringt ihr eigenes Layout über die ganze Breite ohne zusätzlichen Abstand mit. Die Art lässt sich im Inspektor jederzeit wechseln; Ebenen, Werkzeugleiste und Inspektor zeigen Section, Container, Block und Div mit eigenem Symbol. Bestehende Container bleiben, wie sie sind.
- «In Bausteine zerlegen»: Fertige Blöcke – Einstieg (auch mit Bild daneben oder Bild über die ganze Breite), Text, Text mit Bild, Bild, Aufruf, Fragen & Antworten, Zitat, Stimmen, Zahlen, Raster, Aufzählung, Ablauf, Knöpfe und Preise – werden auf Knopfdruck zu einem freien Layout aus Container, Blöcken, Spalten, Titeln, Texten, Bildern und Knöpfen. Texte, Bilder, Links und der Look des Blocks (Hintergrund, Abstand, Design) bleiben; Schriftgrössen, Karten und Linien des Themes werden als Design übernommen, und zentriert das Theme die Titel, bleiben sie zentriert. Danach lässt sich jeder Teil einzeln gestalten, verschieben und ergänzen. In der Werkzeugleiste des Blocks, im Kontextmenü und oben im Inspektor; ein Schritt zum Rückgängigmachen.
- Alle Layout-Vorlagen (Text und Bild, Drei Karten, Aufruf, Zahlen, Fragen, Slider, Reiter, Laufband, Collage, Titel über Bild, Neueste Beiträge, Produkte, Leer) kommen in derselben Struktur auf die Seite: ein Container in Website-Breite, darin Blöcke – so wie die Struktur-Bausteine und die zerlegten Blöcke. «Titel über Bild» hat bis zum eigenen Bild einen dunklen Grund, damit der weisse Text in jedem Theme lesbar ist.
- Eigene Designs wie die Theme Styles in Bricks (Einstellungen → Eigene Designs): ein Design ganz neu aufbauen, auch wenn schon eins aktiv ist – leer von vorn, vom aktuellen Stil aus oder von einem der Stile aus. Einstellbar sind Grundlage (Neutral ohne eigene Handschrift oder ein Stil), alle Farben samt invertierten Bereichen und dunklem Modus, Schriften für Titel und Fliesstext, Grundgrösse und Stufen der Schriftskala, Zeilenabstände, Titel (Stärke, Buchstabenabstand, Grossbuchstaben, kursiv), Knöpfe (eckig, abgerundet, Pille; gefüllt oder umrandet; S/M/L; Grossbuchstaben), Unterstreichung von Links, grösste Inhaltsbreite, Luft zwischen Abschnitten und Rundungen. Jede Änderung erscheint sofort in der Vorschau mit den echten, veröffentlichten Seiten – auf Computer oder Handy, jede Seite wählbar –, die Website bleibt dabei unverändert. Kontrastprüfung für sieben Farbpaare mit «Lesbar machen». Bis zwölf Designs nebeneinander, duplizieren, löschen; «Live schalten» macht eins mit einem Klick zum Design der Website, «Wieder verwenden» kehrt zum gewählten Stil zurück. Neu als Stil: «Neutral».
- Gespeicherte Stile (wie Klassen in Webflow): Im Design-Panel das Design eines Blocks oder Elements «Als Stil speichern», dann wählen ihn andere Blöcke und Elemente aus der Liste. Was eine Stelle selbst einstellt, gilt zusätzlich und geht vor; mit «Stil überall» ändert das Panel den Stil selbst, auf allen Seiten auf einmal und sofort im Editor sichtbar. Lösen übernimmt das Aussehen als eigenes Design, Löschen lässt den Stellen ihr eigenes. Stile gehören zum Design der Website: verwenden darf sie jede:r, anlegen und ändern nur, wer das Design verwalten darf. Auf der Website trägt jede Seite nur die Stile, die sie braucht, mit weniger Gewicht als das eigene Design und mehr als das Theme. Unter Einstellungen → Design stehen alle Stile mit dem, was sie setzen (Abstände, Hintergrund … für welche Bildschirmgrössen und Hover), wie oft und auf welchen Seiten sie verwendet werden – Entwürfe und veröffentlichte Fassungen –, mit Sprung in den Editor, Umbenennen und Löschen.
- Abstände direkt auf der Fläche: Beim gewählten Block oder Element liegen die Innenabstände als Griffe an den vier Kanten (schraffiert beim Darüberfahren). Ziehen ändert den Abstand in 4-px-Schritten, mit Ctrl/⌘ pixelgenau, mit Shift alle vier Seiten, mit Alt die gegenüberliegende dazu – wie im Design-Panel; der Wert steht neben dem Mauszeiger. Gespeichert wird für die Bildschirmgrösse, die gerade gestaltet wird, als ein Schritt zum Rückgängigmachen. Gesperrte Blöcke und sehr kleine Elemente bekommen keine Griffe.
- Jede Vorschaubreite: Neben Computer, Tablet und Handy lässt sich die Vorschau am linken Rand auf jede Breite ziehen (oder mit den Pfeiltasten, mit Shift in 100er-Schritten). Die Bildschirmgrösse, für die man gestaltet, folgt der Breite an denselben Grenzen wie die Website (64 rem und 40 rem); unten steht die Breite mit einem Knopf zurück zur festen Grösse.
- Formular als Element im freien Layout (Gruppe «Interaktiv»): eines der Formulare aus «Inhalte → Formulare» an jeder Stelle eines freien Layouts, etwa in einer Spalte neben Text – mit demselben Spam-Schutz, Eingang und Datenschutzhinweis wie der Formular-Block. Feld-ids tragen die id des Elements; in einer CMS-Liste wird es nicht wiederholt.
- Bilder vom Computer direkt auf die Fläche ziehen: auf ein Bild ersetzt es (weitere Bilder kommen dahinter), in einen Container oder eine freie Fläche kommen sie hinein – auf der Fläche dort, wo man sie loslässt –, auf andere Elemente danach, auf andere Blöcke als neues freies Layout dahinter. Die Ablagestelle ist beim Ziehen umrahmt, die Bilder landen in der Mediathek, alles ist ein Schritt zum Rückgängigmachen; andere Dateien werden mit Hinweis ausgelassen, gesperrte Blöcke nehmen nichts an.
- Interaktionen im freien Layout: Ein Knopf kann statt eines Links ein anderes Element ein- und ausblenden, zeigen oder verbergen – für Infoboxen, Dropdowns, ein eigenes Menü oder einen «Schliessen»-Knopf. Jedes Element lässt sich auf «Anfangs versteckt» stellen; im Editor bleibt es sichtbar und gestrichelt markiert, der Inspector warnt, wenn kein Knopf es zeigt, und listet, wer es steuert. Auf der Website ist es ein echter Knopf mit aria-controls und aria-expanded, Schliessen gibt den Fokus an den öffnenden Knopf zurück, das Einblenden ist kurz animiert (nicht bei reduzierter Bewegung). Beim Duplizieren zielt der kopierte Knopf auf die Kopie seines Elements.
- Schnell einfügen: «/» öffnet beim gewählten Element das Einfügen-Menü (im freien Layout) oder die Block-Bibliothek darunter (bei anderen Blöcken); in Texten bleibt «/» ein Zeichen. Das Element-Menü hat ein Suchfeld über Namen und Beschreibungen, Enter fügt den ersten Treffer ein – auch Komponenten. Der Griff für die Vorschaubreite liegt neben der Seite, nicht darüber.
- Raster einblenden (Knopf mit den Spalten in der Leiste): zeigt über der Vorschau die Inhaltsbreite der Website und ihre Spalten – 12 am Computer, 8 am Tablet, 4 am Handy –, gerechnet mit denselben Werten wie das Theme, damit Elemente bündig sitzen. Fängt keine Klicks ab und wird pro Browser gemerkt.
- Fokuspunkt pro Stelle: Bild-Elemente zeigen im Inspector das Bild mit dem Fokuspunkt aus der Mediathek; ein Tipp ins Bild (oder die Pfeiltasten) setzt ihn nur für diese Stelle – dasselbe Bild kann so in einer schmalen Spalte anders sitzen als in einem breiten Kopf. «Wie in der Mediathek» nimmt die Abweichung zurück.
- Abstände messen wie in Figma: Ist ein Block oder Element gewählt, zeigt Alt (⌥) und Zeigen auf ein anderes die Abstände in Pixeln – zum Nachbarn die Lücke, zum umgebenden Container oder zu einem Element darin den Abstand an allen vier Seiten, bei Überlappung den Versatz der Kanten. Loslassen blendet alles aus.
- Ebenen sperren und ausblenden (im «Aufbau»): Das Schloss sperrt ein Element – auf der Fläche wird es übergangen (ein Klick wählt den Container darum), lässt sich nicht ziehen, verschieben, in der Grösse ändern oder löschen; im Aufbau und im Inspector bleibt es bearbeitbar. Das Auge blendet ein Element nur im Editor aus, um an etwas darunter zu kommen – die Website bleibt, wie sie ist, nichts wird gespeichert.
- Animationen pro Block: Erscheinen (Einblenden, von unten/oben/links/rechts, Heranzoomen, aus der Nähe, aus der Unschärfe, Aufklappen, Schräg, Aufdecken) mit Dauer, Verzögerung, Weg und Verlauf (sanft, federnd, knackig, gemächlich, gleichmässig), Karten und Zeilen nacheinander, auf Wunsch jedes Mal; beim Scrollen Tiefe (Parallax – mit Hintergrundbild bewegt sich das Bild), Ausblenden, Wachsen, Gleiten; Karten bei Hover anheben, vergrössern, leuchten oder in 3D neigen. Die Kacheln im Panel zeigen ihre Wirkung selbst, «Abspielen» spielt sie im Editor ab. Ohne JavaScript oder mit «Bewegung reduzieren» ist alles sofort da; spätestens nach vier Sekunden auch dann, wenn das Skript nicht lädt. Seiten ohne Animation laden davon nichts.
- Pop-ups (unter «Sektionen» → «Pop-up anlegen»): gestaltet mit denselben Blöcken und Elementen wie jede Seite, in ihrem Rahmen und in ihrer Breite. In der Mitte mit abgedunkelter Seite, unten rechts oder als Leiste; erscheinen nach einigen Sekunden, wenn ein Teil der Seite gelesen ist oder wenn die Maus Richtung Tab-Leiste geht. Wie oft pro Person (einmal, pro Besuch, wieder nach Tagen) merkt sich nur der Browser, ohne Cookie. Nur auf bestimmten Seiten oder nicht auf diesen (`/shop/*`), mit Start und Ende in der Zeitzone der Website – auch auf zwischengespeicherten Seiten pünktlich. Höchstens eines pro Seitenaufruf, nie im Editor, in Vorschauen, hinter der Altersprüfung oder auf Seiten wie Warenkorb und Konto; die Frage zur Statistik kommt zuerst. Barrierefrei als echter Dialog: Esc, Klick daneben und Schliessen-Knopf mit Namen, Fokus zurück, benannt nach der ersten Überschrift; das Pop-up unten rechts nimmt den Fokus nicht weg; ohne JavaScript erscheint nichts. Im Editor zeigt das Pop-up seine Wirkung der letzten 30 Tage: gezeigt, geklickt (mit Klickrate) und ohne Klick geschlossen – nur Zahlen pro Tag, ohne Cookie und ohne Angaben zu den Besuchern.
- A/B-Test für Pop-ups: Im Pop-up unter «Seite» ein zweites wählen («A/B-Test: im Wechsel mit»), auch drei oder mehr lassen sich verketten. Jeder Browser lost einmal eines aus und bleibt dabei – auch auf Seiten, auf denen es gar nicht erscheint –, und «schon gesehen» gilt für den ganzen Test. Gezählt wird erst ab dem Tag, an dem alle Pop-ups des Tests laufen. Einen Gewinner nennt Nova erst ab 100 Aufrufen pro Pop-up und wenn der Unterschied in der Klickrate mit 95 % Sicherheit kein Zufall ist (Zwei-Stichproben-Test, bei mehr als zwei Pop-ups strenger); dann beendet ein Klick den Test und nimmt die anderen offline. Keine Cookies, keine Angaben zu Besuchern: die Auslosung bleibt im Browser.
- Kontrast-Prüfung im Editor: Die Vorschau misst laufend, ob Text genug Kontrast zu dem hat, was dahinter liegt (WCAG 2.2: 4.5 : 1, grosse Schrift 3 : 1) – mit den Farben, wie der Browser sie wirklich malt, also auch Theme-Farben, Deckkraft und übereinanderliegende Flächen. Das Design-Panel warnt beim gewählten Block oder Element und schlägt die nächstgelegene lesbare Textfarbe im selben Farbton vor (ein Klick, für die Bildschirmgrösse in der Vorschau); unter «Kontrast» stehen alle schwer lesbaren Stellen der Seite mit Sprung dorthin. Gemessen werden auch Kopf- und Fusszeile (mit dem Weg zu den Farben im Design, denn sie kommen nicht von der Seite) und jeder gestaltete Hover-Zustand: die Prüfung schaltet ihn kurz ohne Übergang ein, meldet nur Farben, die es im normalen Zustand nicht schon gibt, öffnet das Design-Panel auf «Hover» und setzt dort die Textfarbe. Text auf Bildern und Verläufen wird nicht geraten, sondern ausgelassen.
- Freies Layout (Block «Freies Layout»): Seiten aus Elementen bauen wie in Webflow – Container (untereinander, nebeneinander, Raster; als Link oder mit Bedeutung für Suchmaschinen), Überschrift (H1–H4), Text, Bild, Knopf, Symbol, Video, Abstand, Linie, beliebig verschachtelt. Jedes Element hat Inhalt, Design (alles aus dem Design-Panel, pro Bildschirmgrösse und Hover) und Animation (auch «nacheinander» für Container und dauernde Bewegungen wie Schweben oder Pulsieren). Auf der Seite: klicken wählt ein Element, Esc das übergeordnete, die Leiste zeigt den Pfad (Layout › Container › Überschrift) und bietet Verschieben, Einfügen (hinein oder danach), Duplizieren, In Container packen und Entfernen; Texte direkt auf der Seite schreiben; Elemente am Griff in andere Container ziehen – eine Linie zeigt, wo sie landen. Sechs fertige Layouts zum Start (Text und Bild, drei Karten, Aufruf, Zahlen, Titel über Bild, leer). Der Baum wird beim Speichern geprüft (bekannte Elemente, sichere Links, bereinigter Text, begrenzte Tiefe und Grösse) und auf der Seite nochmals maskiert; Überschriften zählen für Gliederung und SEO.
- Interaktive Elemente im freien Layout: Zähler (zählt beim Sichtbarwerden hoch, Zahl mit Schweizer Tausendertrennung schon im HTML), Akkordeon (natives Auf- und Zuklappen, auf Wunsch nur eins offen, sanft animiert, automatisch als FAQ für Google), Reiter (Unterstrichen oder Knöpfe, mit Pfeiltasten bedienbar, Namen direkt auf der Seite schreiben), Slider (bis vier nebeneinander, auf Tablet und Handy weniger, Wischen, Pfeile, Punkte, automatisch weiter nur wenn sichtbar und niemand darauf zeigt) und Laufband (Texte oder Logos endlos, Tempo, Richtung, Anhalten beim Darüberfahren). Jeder Eintrag ist ein Container mit allen Design- und Animationsmöglichkeiten; im Inspector Einträge umbenennen, ordnen, entfernen und hinzufügen – neue übernehmen das Design des letzten. Im Editor öffnet sich die Frage, der Reiter oder die Folie mit dem gewählten Element, Elemente lassen sich hineinziehen, und offene Fragen, gewählte Reiter und Slider-Position bleiben beim Bearbeiten stehen. Ohne JavaScript bleibt alles lesbar; wer weniger Bewegung eingestellt hat, sieht kein Laufen und Zählen. Neue fertige Layouts: Häufige Fragen, Bilder-Slider, Reiter, Laufband; «Zahlen» zählt jetzt hoch. Element-Auswahl nach Grundlagen, Medien, Interaktiv und CMS gruppiert.
- Komponenten wie in Figma und Webflow: jedes Element (eine Karte, eine Preis-Box, ein Team-Eintrag) mit dem Rauten-Symbol als Komponente speichern und unter «Element einfügen» auf jeder Seite einsetzen. Das Original ist eine Sektion der Art «Komponente» und wird im normalen Editor gestaltet; nach dem Veröffentlichen ändert es sich überall. Pro Stelle lassen sich Texte, Bilder, Bildbeschreibungen und Links anpassen – direkt auf der Seite tippen oder im Inspector (leer = wie im Original, «Alle zurücksetzen»). Im Editor ist eine Stelle ein Stück, violett markiert mit ihrem Namen; Doppelklick öffnet das Original, «Von Komponente lösen» macht eine eigene Kopie. Das Design des Originals kommt einmal pro Seite, ids bleiben eindeutig, Komponenten in Komponenten sind begrenzt; eine gelöschte Komponente verschwindet still von der Website. Varianten wie in Figma: im Original unter «Design» eine Variante anlegen («Dunkel», «Klein» …), dann gilt jede Änderung nur für sie – der Canvas zeigt sie sofort; pro Stelle wählt man die Variante im Inspector, der violette Name zeigt sie mit. Sektionen, Komponenten und Vorlagen zeigt ihr Editor nur mit ihren Blöcken, ohne internen Namen. Ihre Texte zählen für die Seite: in der automatischen Beschreibung, in der Suche (Meilisearch und Postgres) und im SEO-Check des Editors.
- Seitenvorlagen für Inhaltstypen (wie Webflows CMS-Vorlagen): in der Liste eines Inhaltstyps «Seitenvorlage» wählen – Nova legt eine Vorlage an, deren Titel, Kurztext, Datum und Bild schon mit den Feldern verbunden sind, und öffnet sie im Visual Editor. Beim Gestalten zeigt sie den neuesten veröffentlichten Eintrag; jedes Element lässt sich mit Titel, Datum, Adresse oder jedem Feld des Typs verbinden. Das Element «Inhalt des Eintrags» zeigt die Blöcke jedes Eintrags oder Novas ganze Ansicht (Kaufen, Tickets, Kommentare) – Shop, Events, Kurse, Immobilien und Profile starten damit. Nach dem Veröffentlichen sieht jede Eintragsseite so aus; Mitgliederinhalte zeigen nur, was ihre Bezahlschranke zeigt, Beiträge bleiben Artikel für Suchmaschinen. Auch der Editor eines Eintrags zeigt die Vorlage: ihre Teile sind ein Stück (violett beim Darüberfahren, Doppelklick öffnet die Vorlage), die eigenen Blöcke des Eintrags stehen bearbeitbar dort, wo «Inhalt des Eintrags» sitzt – fehlt das Element, stehen sie darunter mit einem Hinweis. Bringt die Vorlage eine eigene Hauptüberschrift mit, wird der Titel in Novas Ansicht zur Zwischenüberschrift: eine H1 pro Seite. Blöcke in Beiträgen, Events, Immobilien und Projekten zeichnet der Editor jetzt auch nach Änderungen im Inspector, beim Einfügen und Verschieben sofort neu.
- Freie Fläche und Formen wie in Figma: auf einer «Freien Fläche» liegen Elemente frei übereinander – direkt am Element oder am Griff ziehen, an der Ecke Breite und Höhe ziehen (⇧ hält das Seitenverhältnis; Texte nur in der Breite, ihre Höhe wächst mit den Worten), mit den Pfeiltasten in halben Prozentschritten schieben (⇧ fünf), beim Ziehen rasten sie an Rand und Mitte der Fläche und an Kanten und Mitten der anderen Elemente ein (pinke Hilfslinien, Alt = frei), die Position steht daneben. Mit ⇧-Klick mehrere Elemente wählen: sie ziehen, schieben und löschen sich zusammen, und «Ausrichten» richtet sie links, mittig, rechts, oben, mittig oder unten aneinander aus oder verteilt drei und mehr gleichmässig (ein einzelnes Element richtet sich an der Fläche aus) – jeweils ein Schritt zum Rückgängigmachen. Positionen und Grössen in Prozent der Fläche und pro Bildschirmgrösse – auf dem Handy stehen die Elemente, wo man sie dort hinzieht. Neues Element «Form»: Rechteck, Kreis, Dreieck, Stern, Klecks, Bogen, Ring, Linie, Pfeil, Welle als Vektor, mit Theme-Farben samt Deckkraft, Kontur und Strichstärke, drehbar über «Design». Fertiges Layout «Collage».
- Inhalte aus dem CMS im freien Layout: Element «Inhalte aus dem CMS» zeigt Beiträge, Produkte, Events oder eigene Inhaltstypen – Anzahl, Reihenfolge (neueste, älteste, nach Titel, eigene) und Kategorie wählbar. Gestaltet wird der erste Eintrag wie jedes andere Element; seine Überschrift, sein Text, Bild, Knopf oder ganzer Container wird mit einem Feld verbunden (Titel, Datum, Seite des Eintrags, jedes Feld des Inhaltstyps, auch eigene) – alle weiteren Einträge folgen im Editor sichtbar als Kopien. Neue Einträge erscheinen von selbst; Mitgliederinhalte zeigen in der Liste nur, was auch ihre Bezahlschranke zeigt. Fertiges Layout «Neueste Beiträge» als Start.
- Arbeiten im Editor wie in einem Design-Werkzeug: Aufbau-Panel mit dem Elementbaum jedes freien Layouts (aufklappbar, Zeile antippen wählt das Element, Darüberfahren zeigt es auf der Seite, Zeilen vor, hinter oder in Container ziehen); Rechtsklick-Menü auf der Seite (Bearbeiten, Duplizieren, Kopieren, Einfügen, Design kopieren/einfügen, In Container packen, Verschieben, Entfernen); Tastenkürzel – ⌘D duplizieren, ⌘C/⌘V Blöcke und Elemente kopieren, auch von einer Seite auf eine andere, ⌥⌘C/⌥⌘V Design übertragen, ⌥↑/⌥↓ verschieben, Esc wählt das übergeordnete Element, «?» zeigt alle; Text kopieren bleibt Text kopieren.
- Auf dem Handy bedienbar bis 320 px Breite: Editor mit «Veröffentlichen» immer sichtbar (Panels wischen seitlich), «Block darunter einfügen» in der Block-Leiste statt Hover-Linie, Dialoge und Suchlisten öffnen ohne die Tastatur, Listen blenden Nebensachen aus, Tabellen im Admin (Einträge, Bestellungen, Formular-Eingänge, Mitglieder, Tickets, Protokoll …) werden zu Karten – erste Spalte als Titel, leere Werte weggelassen; auf der Website brechen lange Wörter in Titeln um (mit Silbentrennung), Brotkrümel und Logo sind gross genug zum Tippen. Lange Menüs klappen schon auf breiteren Bildschirmen in den Menü-Knopf, statt über den Rand zu laufen – die Kopfzeile schätzt den Platz aus Einträgen, Logo und Sprachen.
- Unbegrenztes Rückgängig/Wiederholen (300 Schritte im Speicher), Versionsverlauf mit Vergleich und Wiederherstellen.
- Entwürfe, «Zur Freigabe» für Autoren, geplante Veröffentlichung, Änderungen verwerfen, offline nehmen; Ablaufdatum («Läuft ab» im Veröffentlichen-Menü): ein Angebot oder Hinweis geht zur gewählten Zeit von selbst offline, bleibt als Entwurf, und wer veröffentlicht, bekommt eine Benachrichtigung; die Listen zeigen «bis …».
- Redaktionskalender (Inhalte → Redaktionskalender): Monatsansicht mit allem, was erschienen ist (grün), geplant ist (orange) und abläuft (rot), pro Tag mit Symbol des Inhaltstyps; Geplantes und Ablaufendes per Ziehen auf einen anderen Tag verschieben (gleiche Uhrzeit), volle Tage mit «+ n weitere», «Nur Geplantes» als Filter; auf dem Handy als Tagesliste.
- Mehrfachauswahl in den Listen von Seiten und Inhalten: Kästchen pro Zeile (auch auf dem Handy in der Karte), «alle» im Tabellenkopf, Esc hebt auf; eine schwebende Leiste veröffentlicht, nimmt offline (mit Rückfrage), setzt die Kategorie (mit Vorschlägen), dupliziert oder legt in den Papierkorb (mit «Rückgängig» für alle). Jeder Eintrag wird wie eine einzelne Änderung geprüft – Rechte, Hooks, Pflichtfelder –, was nicht geht, steht mit Grund in der Meldung; die Startseite ist nicht wählbar.
- Papierkorb: Gelöschtes landet erst dort – ohne Rückfrage, mit «Rückgängig» direkt in der Meldung – und bleibt 30 Tage. Zurückgeholt wird alles: Adresse, Status, Verlauf, Übersetzungen, Team- und Leserkommentare; ist die Adresse inzwischen vergeben, kommt der Eintrag unter neuer Adresse als Entwurf zurück. Endgültig löschen und leeren nur mit Löschrecht, Autor:innen sehen nur eigene. Ein widerrufenes Profil (Einwilligung) geht nie in den Papierkorb.
- Globale Elemente: Header, Menü (mit Untermenüs), Footer, wiederverwendbare Sektionen.
- 404-Protokoll (Einstellungen → Suchmaschinen und Werkbank → Weiterleitungen): jede Adresse, die ins Leere führt, mit Anzahl Aufrufe, letztem Aufruf und Herkunftsseite, die häufigsten zuerst. Nova schlägt die passende Seite vor (gleiche Adresse an anderem Ort, eine, die so anfängt, oder eine, mit der sie anfängt); ein Klick macht daraus eine 301-Weiterleitung, oder die Adresse wird ignoriert. Anfragen nach fremden Systemen (wp-login.php, .env …) zählen nicht; Einträge verschwinden nach 90 Tagen ohne Aufruf.
- Content-Typen mit 22 Feldtypen inkl. Relationen, wiederholbaren Gruppen und Validierung; im Studio automatisch als Formular mit Live-Vorschau, in der Werkbank mit Schlüsseln und als JSON editierbar.
- Sammlungsseiten mit Kategorie-Filter, Schlagwörtern und Paginierung.
- Filter in jeder Inhaltsliste: neben Suche und Status nach Person («Mir» oder jemand aus dem Team), letzter Änderung (heute, 7, 30, 90 Tage) und nach jedem auswählenden Feld – Kategorie, Auswahlfelder, Schlagwörter, Ja/Nein –, jeweils mit Anzahl. Aktive Filter stehen als Chips über der Liste und gehen einzeln oder alle weg. «Als Ansicht speichern» legt die Filter als einen Klick über die Liste, für sich selbst oder – wer veröffentlichen darf – für das ganze Team.
- Suchen und Ersetzen über alle Inhalte (Inhalte → «Suchen und Ersetzen»): eine neue Telefonnummer, ein umbenanntes Produkt, eine alte Adresse auf allen Seiten, in allen Einträgen und Übersetzungen auf einmal. **Medien**
- Mediathek mit Ordnern, Schlagwörtern, Suche, Drag & Drop und Upload vom Handy. Ordner sind eine Leiste über den Dateien: «Alle Dateien», «Ohne Ordner» und jeder Ordner mit Anzahl; «Neuer Ordner» legt einen an, auch leer; Hochgeladenes landet im gewählten Ordner; Dateien (auch mehrere gewählte) zieht man auf einen Ordner, um sie zu verschieben. Umbenennen nimmt alle Dateien mit, ein bestehender Name führt beide zusammen; Löschen lässt die Dateien stehen («Ohne Ordner»). Die Bildauswahl im Editor filtert ebenfalls nach Ordner.
- Typprüfung über den Dateiinhalt (nicht die Endung), keine SVG-Uploads (XSS).
- AVIF/WebP/JPEG in 9 Breiten, on-the-fly erzeugt und im Bucket gecacht, `srcset`/`sizes`, Lazy-Loading, Fokuspunkt.
- Jeder Upload wird vor dem Speichern geprüft – aus der Mediathek, aus dem Import und aus Formularen der Website: keine Programme, keine Office-Makros oder ActiveX, keine ZIP-Archive mit Programmen oder Skripten, keine PDFs mit JavaScript, Startbefehlen oder angehängten Dateien (auch in komprimierten Streams und mit maskierten Namen). Mit `CLAMAV_HOST` prüft zusätzlich ClamAV jede Datei mit seinen Signaturen; Funde werden abgelehnt und als Benachrichtigung gemeldet, und ist ClamAV eingerichtet, aber nicht erreichbar, wird nichts ungeprüft gespeichert. Die Mediathek zeigt bei jeder Datei, wie sie geprüft wurde.
- Videos werden nach dem Hochladen im Hintergrund fürs Web aufbereitet (ffmpeg, eines nach dem anderen): H.264/AAC-MP4 mit dem Index am Anfang (Wiedergabe startet sofort) in 1080p und 720p – nie grösser als das Original –, dazu ein Vorschaubild aus dem Video. Die Website spielt auf breiten Bildschirmen 1080p, sonst 720p, mit Byte-Ranges zum Spulen; das Original bleibt für Downloads und als letzte Rückfallebene. Ist das Original schon ein H.264-MP4 und kleiner, läuft es direkt. Die Mediathek zeigt den Stand (in Arbeit, fertig mit Grössen, Fehler mit «Nochmals versuchen»); ältere Videos und durch einen Neustart unterbrochene werden beim Start nachgeholt. Ohne ffmpeg oder mit `NOVA_VIDEO=off` laufen Videos wie hochgeladen.
- Nicht-destruktives Bearbeiten im Browser: Zuschneiden (mit Seitenverhältnis), Drehen, Helligkeit.
- Datei ersetzen: neue Version hochladen, alle Seiten, Einträge und Einstellungen zeigen sofort die neue – gleiche Art von Datei (Bild durch Bild), wieder geprüft wie jeder Upload, Bearbeitungen beginnen neu. Mehrfachauswahl in der Mediathek (Kreis auf der Kachel, Cmd/Ctrl-Klick, danach jeder Tipp): in einen Ordner, Schlagwort ergänzen, löschen – verwendete Dateien bleiben, bis man «Trotzdem löschen» wählt.

Vor dem Installieren steht, was dazukommt; Nova merkt sich, was eine Erweiterung angelegt hat: Aktualisieren ersetzt genau das (neue Felder kommen dazu, bestehende bleiben, ausgeschaltete Hooks bleiben aus), Entfernen nimmt genau das zurück und behält, was Menschen geschrieben haben – Inhaltstypen mit Einträgen, Formulare mit Eingängen, eingesetzte Sektionen. - Hooks: eigene JavaScript-Funktionen vor dem Speichern (Daten ändern oder ablehnen), vor dem Veröffentlichen (prüfen) und vor dem Absenden eines Formulars (Felder ändern, ablehnen mit Meldung an den Besucher, still als Spam verwerfen) – pro Inhaltstyp oder für alle. Sie laufen in QuickJS als WebAssembly, einer eigenen JavaScript-Engine ohne Netz, Dateien, Prozess und Timer, mit 50 ms und 16 MB pro Aufruf und frischem Zustand bei jedem Aufruf. Code wird beim Speichern geprüft; «Mit echten Daten testen» zeigt Eingabe, Ergebnis, `console.log` und Laufzeit, ohne etwas zu speichern.

**Git-Sync mit GitHub Actions** – `content/` im Repository, Token als Secret `NOVA_TOKEN`:

```yaml
# .github/workflows/nova.yml
on:
  push: { branches: [main], paths: ['content/**'] }   # Git → Website
  schedule: [{ cron: '17 * * * *' }]                    # Website → Git, stündlich
jobs:
  sync:
    runs-on: ubuntu-latest
    permissions: { contents: write }
    env: { NOVA_TOKEN: '${{ secrets.NOVA_TOKEN }}' }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: curl -fsSO https://deine-website.ch/api/v1/cli.mjs
      - if: github.event_name == 'push'
        run: node cli.mjs push --publish
      - run: node cli.mjs pull
      - run: |
          git config user.name nova && git config user.email nova@users.noreply.github.com
          git add content && git commit -m "Inhalte von der Website" && git push || true
```

## Preview-Deployments pro Branch

Railway kann für jeden Pull Request eine eigene Umgebung starten – mit eigener Datenbank und eigenem Bucket:

1. Im Railway-Projekt unter **Settings → Environments** die **PR Environments** einschalten.
2. In der Haupt-Umgebung die Variable `NOVA_PREVIEW_DEMO` setzen, z. B. `restaurant` oder `shop:kante` (Sparte, optional Stil). Die PR-Umgebungen übernehmen sie; in der Haupt-Umgebung selbst wirkt sie nicht.
3. Pull Request öffnen: Railway baut ihn, Nova erkennt die PR-Umgebung am Namen, richtet auf der leeren Datenbank eine Demo-Website ein und schreibt die Anmeldung einmal ins Deploy-Log.

In jeder Vorschau-Umgebung sperrt Nova Suchmaschinen aus (`X-Robots-Tag`, `robots.txt`, `noindex`) und zeigt im Admin oben einen Hinweis. Schliesst man den Pull Request, räumt Railway die Umgebung samt Daten weg.

## Continuous Integration

`.github/workflows/ci.yml` läuft bei jedem Push und Pull Request:

- **Typen, Tests, Build** gegen ein echtes Postgres (mit ffmpeg für den Video-Test).
- **Lighthouse** (mobil, je 3 Durchläufe) für alle vier Stile mit ihrer typischen Sparte: `scripts/demo-site.mjs` richtet eine frische Website so ein, wie es eine Person im Setup-Assistenten tun würde, und misst Startseite, Seiten, Listen und je eine Detailseite. Fehler, wenn Performance, Barrierefreiheit, Best Practices oder SEO unter 95 fallen oder CLS über 0,05 steigt; LCP über 1,8 s und TBT über 150 ms als Warnung. Die Berichte liegen als Artefakt beim Lauf.

Lokal gemessen (Lighthouse 12, mobil): Kante, Salon und Feuilleton 100/100/100/100 mit LCP 1,1–1,7 s, Bistro 100/100/100/100 mit LCP 1,4–1,7 s (vorher 1,7–2,1 s), CLS überall 0.

## Was (noch) nicht umgesetzt ist

Ehrlich aufgelistet – vieles davon ist in der PRD ohnehin P1/P2:

- Einen öffentlichen, von Nova betriebenen Marktplatz mit Erweiterungen von Drittanbietern, Bewertungen und bezahlten Erweiterungen gibt es nicht: Das wäre ein eigener Dienst mit Prüfprozess und Zahlungsabwicklung, kein Teil des CMS. Nova bringt seinen geprüften Katalog mit und liest beliebig viele eigene, signierte Kataloge – das Werkzeug dafür liegt bei.
